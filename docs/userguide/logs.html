Logs and data folder

Steward writes a log file and a few other files into its own folder. The log is the first thing to look at when something seems wrong, and the first thing to attach when you report a problem.

The steward folder

Steward keeps its files in a steward/ folder inside the client folder (<TSO client folder>/steward/). The Settings screen shows the exact path: open Settings…, group General, card About, field Data folder. If steward cannot use that folder, the field reads No writable steward folder.

  • logs/console.log: the current log. Older logs sit beside it as console.log.1, console.log.2 and so on, the lowest number being the newest.
  • dumps/: files written by the Diagnostics probes.
  • adventure templates, written by the Adventures module.
  • backups/: settings backups the Updates module takes before an install.

If the log folder cannot be used, steward falls back to its application storage folder and then to the documents folder, and writes a note about it at start-up.

The Logging settings

Open Settings…, group General, card Logging:

  • Write the log to a file: switches the file on or off. The path is shown under the label.
  • Include debug lines: much more detail, for bug reports. Off by default.
  • Start a new file every day: also starts a new file at the first line written on a new day.
  • Start a new file at: the size in MB at which the current file is closed and a new one starts. 0 turns this off.
  • Old files to keep: how many older files are kept. 0 keeps none.

Save applies these at once, with no reload. With the defaults the log files together take at most about 40 MB.

Reading a log line

A line looks like this:

[LOG]   [2026-04-26 14:32:01] [collect] queued 3 collectibles, 1 lootable

It holds a level (LOG for normal events, WARN for a surprise steward recovered from, ERROR for something that broke, DEBUG only with debug lines on), the time, the module or area, and the message.

A few lines show that steward is healthy. At start-up one line begins boot complete and names the version and the number of modules. While running, a heartbeat line from the scheduler appears about every 15 minutes. A deferring line means a game dialog is holding the action queue, and a resumed line says it moved on again.

What to attach to a problem report

  • the version (Build in the About card);
  • logs/console.log, and for a bug that you can repeat, a log taken with Include debug lines on;
  • files from dumps/ if a Diagnostics probe was involved;
  • what you did and what you expected.
