Troubleshooting

Common symptoms, what to check and what to do. The log (Logs and data folder) is the first place to look for most of them.

The ~Steward~ menu does not appear

The script was not loaded.

  • Check that user_steward.js is in the client's userscripts/ folder (<TSO client folder>/userscripts/).
  • Reload scripts from the client menu, or restart the client.
  • Open the client's scripts manager and check that steward is not switched off. If it was switched off while steward ran, reloading does not stop it, so restart the client.
  • Look under the client's Tools menu: with a menu style other than grouped, steward sits there.

Steward does nothing

  • Look at the first item of the menu. Steward: ✕ Paused means everything is paused. Click it to resume, or use Automation on the dashboard's Overview.
  • Check that the module is on: its quick toggle in the menu shows ✓, and the dashboard tab's dot is lit.
  • Check the menu's status line. queue held N min means a dialog on screen is holding the actions; close it. If no steward window is visible, the game layer may be covering it, and restarting the client clears that.
  • Look in the log for a heartbeat line about every 15 minutes. No heartbeat for longer means the timer stopped.
  • A tick gap warning says the timer was held back, for example by a locked or disconnected session.

There is no log file

  • Check Write the log to a file in the Logging card (Settings…, General).
  • Check the Data folder field of the About card. No writable steward folder means steward found no place to write.
  • Look for the fallback folders named in Logs and data folder.

An update was not installed

  • Open the Updates menu or the Updates group on the Settings screen and run a check. Steward checks on start at most once per hour; nothing installs without a confirm unless automatic install is on.
  • If GitHub cannot be reached, check the connection and try again.
  • An update is installed only when its size, checksum and version match. A release with no published checksum cannot be installed automatically.
  • Test releases and releases older than 0.12.0 show up only when the matching switches in the Updates group are on. A development build is never installed automatically.

See Updates.

A scenario run paused on its own

The run stops with a reason instead of guessing. Known cases:

  • BuffFailed: a burst of buffs could not be sent completely. Resume sends every grid again, including the ones that already went out, so check the star menu stock first.
  • Quest objects of an unread quest are not clicked until the quest is read.
  • The final clean-up waits for quest objects it may never be able to click and then pauses after its pick-up limit.

See Scenario runs.

A wave run pauses as Unreachable or AttackRefused

  • Unreachable: an attack line in a wave needs a path that opens only when a buff line of the same wave kills a blocking camp. Put the buff kill in an earlier wave.
  • AttackRefused: a buff and then an attack on the same camp in one wave, where the buff kills it. Drop the attack line, or move the buff to an earlier wave.

See Wave runs.
