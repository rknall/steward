Checks GitHub for newer steward releases and installs one on your confirmation, with a settings backup first.

What you can do

You want to know whether a newer steward exists.

Steps
  1. Open the ~Steward~ menu, then the Updates submenu.
  2. The first line shows the status. Choose Check for updates now to look again.
Result
A game alert tells you the result. By default steward also checks once when the client starts, at most once an hour.

You want to install a newer release.

Steps
  1. Open ~Steward~, then Updates, and choose Install v… (the entry names the new version; it reads Updates… when none is waiting). This opens the Updates group of the Settings screen.
  2. In the release card press the Install button and read the confirm box.
  3. Confirm.
Result
Steward downloads the release, verifies it, saves your settings to a backup, writes the new file and reloads the scripts. If the client cannot reload scripts, restart it.

You want to go back to an older version.

Steps
  1. Open the Updates group of the Settings screen.
  2. In the "Versions" card press Install next to the older release and confirm.
Result
The settings saved when you left that version are restored. Without an exact match the newest backup from an older version is used, and with none your settings stay as they are. The "Settings backup restored" column shows which.

You want updates to install without asking.

Steps
  1. In the Updates group, under "Update options", switch on "Install updates automatically".
  2. Press Save.
Result
A newer plain release is installed when steward is idle and the release has a checksum. A settings backup is made first.

How an install is checked

The file comes only from the steward repository's releases on GitHub. Before it is written, steward checks that its size matches the release, that its SHA-256 checksum matches the one GitHub lists, and that it is the version the release names. A download that fails a check is rejected and nothing changes. If a release lists no checksum, it is not installed automatically and the confirm box says it is checked by size and version only.

Steward then saves your settings as a backup file in steward/backups and keeps the old script next to the new one as user_steward.js.backup. All profiles share the script file, so an install changes the version for every profile.

Settings

All of these are in the Updates group of the Settings screen, under "Update options"; changes apply with Save.

checkOnStart

Default: On

Shown as "Check for updates when the client starts". At most one check an hour, whatever you set.

Change it when you do not want steward to contact GitHub on start. You can still check by hand.

autoInstall

Default: Off

Shown as "Install updates automatically". Releases only; a settings backup is made first.

Change it when you want steward to stay current without asking. Leave it off if you prefer to confirm each install.

showPrereleases

Default: Off

Shown as "Show test releases". Adds alpha and beta releases to the Versions list and to update checks. A test build always sees them.

Change it when you want to try test releases.

showOldReleases

Default: Off

Shown as "Show versions before 0.12.0". Those releases have no updater: after installing one, steward cannot update itself and you must copy the file into userscripts by hand.

Change it when you need to go back past the first release with an updater.

keepBackups

Default: 20

Shown as "Settings backups to keep". Older backups of this profile are deleted after each install. The value must be at least 1.

Change it when you want a longer or shorter history to step back to.

Notes

  • A development build is shown as such and is never installed automatically.
  • A backup holds all steward settings, never the updater's own state, and only the current profile's backups are listed.
