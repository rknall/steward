Adventures runs a whole series of adventure maps for you, from home and back, either from a scenario that steward already knows or from a run template you build.

What you can do

You want to run a built-in scenario, such as Storm Recovery or Twins.

Steps
  1. Go home.
  2. Open the ~Steward~ menu of the client, then Adventures, then the Scenarios folder.
  3. Choose the scenario. A row ends in a count such as ×2, the maps of that adventure in your star menu. A row with ×0 is greyed out, because you have no such map.
  4. Answer the prompt How many consecutive runs with the number of runs you want, up to the maps you have.
  5. If a map of that adventure is already open, steward also asks Start at which trip. Answer 1 to start from the beginning.
Result
The run starts. At home it produces the items the first trip needs, starts the map and applies the items on the island while the quests ask for them. Collect Pickups finishes each trip, then the run closes the map and goes on to the next one. It needs no generals.

You want to build a run template for your own attack adventure and run it.

Steps
  1. Open the Settings screen, then the Adventures group, and choose Run templates…. The ~Steward~ › Adventures menu has the same Run templates… entry.
  2. In the window Steward adventures, choose New template.
  3. Fill the Template card: a Label (the name shown in the menu), the Adventure, and the Loadout battle file (Choose…).
  4. In Speed, switch Use a horseshoe on if you want one, and pick it in Horseshoe. In On arrival, Send all to the star on arrival is on by default.
  5. In Waves and steps, choose Add waves… and pick the battle files in the order they run. Drag a row or use the arrows to reorder them.
  6. Choose Save template. It stays disabled until the template has everything it needs, and the footer says what is missing.
  7. Go home, or view the adventure island, then open ~Steward~ › Adventures and choose the template. Answer how many consecutive runs you want. From the island steward also asks Start at which wave.
Result
The template is a file in the steward folder, so you can share it, and it survives a profile switch. The run musters the loadout generals, starts the map, sends the waves and closes the map, then retrains if you switched that on (see Settings).

You want to pause, resume or end a run that is under way.

Steps
  1. While a run is running or paused, the ~Adventures~ menu appears in the client's menu bar. It is not there when no run is active.
  2. Open it. The top rows show the run title and where it stands.
  3. Choose Pause run while the run is running. Choose Resume run while it is paused: the run enters the step it stopped at again, so nothing is skipped.
  4. Choose End repetition to finish the run in progress and not start another one, when you asked for more than one run.
  5. Choose Stop run to drop the run and its request.
Result
Each command is greyed out unless it applies now. The menu also lists the steps of the run in groups, with a mark for done, current and not yet reached, and a step that does not apply to the run shows not used. When a check fails the run pauses and the status line says where it stands and why. The same four commands are also in the ~Steward~ › Adventures menu.

You want a run to do something between two waves, such as unloading generals or pausing for you.

Steps
  1. Open your template in Run templates and go to the Waves and steps card.
  2. Choose Add step…. In the Add a step card pick Unload generals, Send generals home, Pause with a sound or Pause x min, and where it goes (At the end or After wave a number).
  3. Save the template.
Result
The step runs between those two waves, never inside a battle file. A step can only be changed by removing it and adding a new one.

You want to run several maps one after another, for example a short map while the generals of a long map travel home.

Steps
  1. Open Run templates… and switch the window from Templates to Queues.
  2. Create a new queue and give it a Label. A queue without a label, or with a label another queue already uses, is refused at save.
  3. Choose Add entry. The select lists your templates under Adventures and the built-in and own scenarios under Scenarios. Give each entry its own number of runs.
  4. Set the options you want: loop the whole queue (with an optional limit on passes), start the next entry early, retrain, and what to do when an entry has no map.
  5. Save the queue.
  6. Go home, open ~Steward~ › Adventures and choose the queue in the Queues folder after Scenarios. A row reads the label and the number of entries, with the map count of the first entry. A row with a count of 0 is greyed out.
Result
The queue starts at its first entry. Steward asks only that entry's start questions (start wave for an open template map, start trip for an open scenario map) and does not ask how many runs, because each entry has its own count. When an entry's last run is done, the next entry begins by itself. The status line reads the queue label and the entry, for example Short then long 2/3, with the pass when the queue loops.

You want to move a queue on to its next entry without waiting for the current one.

Steps
  1. Go home and pause the run, or wait for it to pause.
  2. Open ~Steward~ › Adventures and choose Skip entry. It is greyed out unless a queue is paused and you are at home.
Result
If the entry's map has not been started yet, its remaining runs are dropped without counting and the next entry begins. If the queue paused because an entry could not start, that entry is stepped over and the queue carries on by itself. If the next entry cannot begin either, a notice says why and the queue stays paused.

Scenario runs

A scenario run plays a scenario adventure without generals. Each trip to the map applies items to their grids, picks up what the quests ask for and returns home to produce the next trip's items. Steward ships these scenarios, listed in the Scenarios folder, in a sub-folder per campaign when the adventure has one:

  • A New Experience
  • Heart of the Wood
  • Hero Wanted
  • Nothing Special
  • Retro Style
  • Riches of the Mountain
  • Save the Towns
  • Storm Recovery
  • The Jester's Map
  • Twins
  • Where Do Easter Eggs Come From?

How a scenario run behaves:

  • Start from home. A scenario can only be started at home. If steward cannot read an item the scenario needs, the start is refused and nothing is stored.
  • Production first. The run leaves home only when the items of the trip are in stock and nothing of them is still queued. It waits as long as that takes.
  • Only what a quest asks for. On the island an item is applied and an object picked up only while a running quest asks for it, so nothing is wasted on a quest that does not take it.
  • Waiting between maps. The run waits 180 seconds after the last map it saw closed before it starts the next one. The wait also holds across Stop, a new start and a client restart.
  • Your own scenario files. A scenario file with the same name as a built-in one in the adventures/scenarios folder of the steward data folder replaces the built-in one. A file that cannot be read is listed greyed out as a broken scenario file, so you can see why it is missing.

For the exact file format and every rule, see the scenario notes in the repository documentation. Problems you may meet are collected on the Troubleshooting page.

Queues

A queue is a saved, ordered list of templates and scenarios, each with its own number of runs. It runs inside the normal run, so the same pauses, commands and restart handling apply.

  • Hand-over. If the next entry's generals are not home yet, the queue waits for them. The 180 second wait after the last map holds across entries, so the next entry never starts a map too soon.
  • Early start. With early on, the next entry starts while the generals of the finished template travel home, as long as it uses a different template or is a scenario. The finished entry then skips its retraining.
  • Loop. A looping queue repeats from the first entry until you choose End repetition or Stop run, or until the pass limit you set is reached.
  • No map left. With pause, an entry without a map pauses the queue, as a single run does. With skip, the entry is stepped over with a log line and a notice. If every entry lacks a map the queue pauses.
  • Retrain. The queue can follow the Retrain lost troops setting, or force it on or off for every entry. A scenario entry retrains nothing either way.
  • Edits. A running queue uses its own copy. Changes you save apply at the next start, and the edit view warns you about it.
  • Restart. A client restart in the middle of a queue resumes on the entry it was on.
  • Broken entries. An entry whose template or scenario is gone, or of a kind this build does not know, stops the queue from starting until you remove it.

Each queue is its own file in the adventures/queues folder of the steward data folder. For the file format and every rule, see the queue notes (docs/QUEUES.md) in the repository documentation.

Wave runs

A wave run plays the waves of your template one after the other. Within a wave the attack and buff lines go out in file order: the first at once, and each later one after its own delay.

  • Buff lines. A buff line aimed at a camp is applied from the star menu. It counts as done when your stock drops, not when the camp dies, so a buff that only weakens a camp does not hold the wave. A later line on a camp that a buff killed is dropped.
  • Send all to the star. After arrival every general goes to the star empty, so each wave loads from a known state. The Send all to the star on arrival switch in the template turns this off, and the run menu then shows Send all to the star as not used.
  • Starting in the middle. From the island you choose a start wave. Wave 1 runs the steps before it as well. A later wave starts at its own battle file and skips the steps before it, because they belong to the part of the map already played.

Two things a wave run cannot do:

  • An attack line whose path opens only when a buff line of the same wave kills a blocking camp. The wave waits and the run pauses as unreachable. Put the buff kill in an earlier wave.
  • A buff and then an attack on the same camp, where the buff kills it. The attack is refused and the run pauses. Drop the attack line, or move the buff to an earlier wave.

Settings

These settings are in the Adventures group of the Settings screen. They are saved with the screen's own save button. Run templates and queues are not settings: each one is its own file.

lastDir

Default: empty

The folder where the battle-file picker opened last, so the next pick starts there. It has no control on the Settings screen: steward writes it when you pick battle files in the template window.

Change it when you do not need to: it only saves you browsing to the same folder again.

stuckMinutes

Default: 45

The Stuck step limit, in minutes, in the card Running an adventure. A step on the island that has waited this long goes home and back, which makes the client refresh what it reports. 0 turns it off.

Change it when a run seems to wait for something that has already happened. Values below 10 let the trip fire during the normal waits of a scenario run, which only costs travel time.

retrain

Default: off

The Retrain lost troops switch, in the card After each map: orders the troops lost on a map back, for every run. It is read again each time a run reaches the retrain step, so changing it takes effect in the middle of a run. A running queue can override it with its own retrain option.

Change it when you want every run to restore its army without your help.

retrainSettlersOnly

Default: off

The Only with enough settlers switch, also in After each map. While retraining is on, a run that lacks the free settlers for the orders, and cannot top them up with a population buff, skips retraining and carries on instead of pausing. It is greyed out, with the note Needs Retrain lost troops, while retraining is off; its stored value is kept.

Change it when an unattended series should keep going even if it cannot retrain every map.

Notes

  • The run only acts while you view the right zone: home, the run's island, or either, as the current step needs. On another zone nothing is sent and nothing pauses, and the run carries on when you view the right zone again.
  • A run survives a script reload or a client restart. Its state is kept in its own file, so it picks up again without sending an order twice.
  • Scenario runs let Collect Pickups click quest objects on the island. If Collect Pickups cannot do that, the start warns that quest objects will not be clicked.
  • The Overview tile of Adventures shows whether a run is active and how many run templates you have, with links to Templates and Settings.
